## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的整体覆盖率很高，但新改动的代码经常没被测到，希望只考核本次变更的行。请从零实现一个增量覆盖率门槛组件。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 输入两部分数据：变更行清单（文件、行号范围）与覆盖率数据（文件、行号、是否被执行）；2) 计算增量覆盖率：只统计变更行中被执行的比例，未覆盖的行要列出明细；3) 支持门槛：增量覆盖率低于配置值时返回失败，并输出未覆盖行清单；4) 支持排除规则：生成的代码、配置文件等可按路径或标记排除，排除项不计入分母；5) 支持变更行跨函数边界的处理：行号范围与覆盖率数据未对齐时要有明确策略并避免误判；6) 支持多次变更累计：把多个提交的变更行合并计算，去重后统计；7) 提供统计：变更行数、覆盖行数、排除行数、覆盖率与门槛结果；8) 测试覆盖增量覆盖率计算、门槛失败、排除规则、行号对齐、多次累计与统计；`mvn -q verify` 一条命令跑通。
